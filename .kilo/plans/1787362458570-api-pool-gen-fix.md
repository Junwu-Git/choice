# API 设置修复 + 条目池 AI 生成功能

## 背景与目标

两件事：

1. **API 设置页修复**（`src/components/ApiEditor.vue`）
   - 配置名称输入框当前在卡片**底部**（`.choice-api-bottom-row`，第 83 行），需移到每个条目**顶端**。
   - Bug：「生成 API」下拉遍历 `draftApis`（未保存草稿，第 101 行），导致新增/修改但未点保存的配置立即出现在下拉里。修复为：下拉只遍历**已保存**的 `globalStore.settings.apis`，活动选择仍作为草稿随「保存」一起提交。

2. **条目池 AI 生成功能**（新增）：在条目池编辑器加「AI 生成」入口，弹对话框，用户输入条目数 X + 要求，AI 生成 X 条候选行动条目，可重 ROLL，满意后注入用户选择的层级（全局/角色/聊天）。

## 已确认决策

- **生成上下文**：始终带角色描述/性格/场景（贴合角色语气）；提供「结合近期对话」复选框（默认开），开启时纳入 `prompt_rules.context_rounds` 轮聊天历史。
- **提示词**：条目池生成用**内部写死**的精简系统提示词，不进 PromptEditor、不加 schema 字段。用户通过对话框「要求」文本框控制方向。
- **活动 API 绑定**：下拉只列已保存配置；活动选择仍为草稿，点「保存」时与列表一起提交。

## 其余实现约定（按代码库惯例，无需再确认）

- 生成条目只产出 `text`；其余字段 `pinned=false, weight=1, category='', condition=''`，复用 `PoolEntry` 形状。
- 复用活动 API（`chatStore.active_api_id` + `globalStore.apis`），与 `generateOptions` 同一套。
- 条目池生成**不**用思维链预填充（区别于行动选项生成）；走 `stream` 由 `api.stream` 决定。
- 抽取共享 API 调用逻辑到新文件 `src/core/api-client.ts`（导出 `callSecondaryApi`），`generateOptions` 与 `generatePoolEntries` 共用，`@sillytavern` 限定在 `src/core/`。
- 取消机制仿现有 `generatorState`/`cancelGeneration`：模块级 `poolGenController: AbortController | null` + `cancelPoolGen()`，对话框取消按钮调它。
- 注入由对话框 `emit('confirm', { entries, layer })`，`PoolEditor` 用现有 `poolOf(layer)` push（与「复制选中到聊天层」同一通道）。
- 对话框用 `Teleport to body` 模态浮层（仿 `FloatingSettings.vue` 的 overlay 写法，居中、不可拖拽即可）。
- i18n：新 `t\`中文\`` 串需在 `i18n/en.json` 增加对应英文键（键=中文字符串）。
- 代码注释中文、简洁、解释「为什么」。

## 风险与边界

- `callSecondaryApi` 抽取后须保证 `generateOptions` 行为逐字不变（仅改名 + 搬位置），回归行动选项生成一次。
- 条目池生成与行动选项生成共用活动 API；若用户活动 API 未配置或失效，两条路径报错一致（`resolveCustomApi` 返回 undefined → toastr 提示）。
- `parsePoolEntries` 宽松解析：编号/无序列表/纯文本均兼容；不依赖 `<options>` 标签（与行动选项解析刻意分离，勿合并逻辑——两者输出契约不同）。
- 注入层级覆盖语义：注入到低层（如全局）后，若聊天层非空，新条目本轮抽取不生效（覆盖式），属预期行为，对话框内给一行提示即可。

## 范围外

- 条目池生成提示词的用户可编辑性（后续按需再加 schema 字段 + PromptEditor 区）。
- 生成条目的 `category`/`condition` 自动填充（仅 `text`）。
- 独立的条目池生成 API 选择（复用活动 API）。
