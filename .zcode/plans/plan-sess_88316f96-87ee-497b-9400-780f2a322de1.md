# 新手引导重构：分层引导方案

## 目标

新用户 3 分钟内走通「配 API → 生成 → 点选」核心链路；功能介绍从"一口气 22 步灌完"改为按需深入；卡住时引导主动召回。全部 UI 基于 shared 设计系统组件与 `--choice-*` token，不新增持久化 schema 字段。

## 现状问题（已核实）

- **22 步聚光灯向导**（`src/core/onboarding.ts` + `OnboardingWizard.vue`）强制新手逛完全部 8 个页面；`done` 自动检测仅 2 处，其余纯手动翻页；跳过/中断后重放永远从第 1 步开始。
- **触发被动**：仅悬浮设置面板打开时自动弹一次（`maybeAutoOpenOnboarding` 弹出瞬间即置 `onboarding_done`）；不碰设置就永远见不到。
- **卡点无召回**：未配 API 点生成只弹 toastr（generator.ts:702），引导不出现；悬浮球 disabled 只变暗无说明；面板空状态只有文字。
- **文案三处平行来源已漂移且有事实错误**：22 步向导 + `GUIDE_CONTENTS` 8 段 + 3 个弹窗内嵌 guideHtml。错误包括：「自动生成仅对当前聊天生效」（实为全局字段）、「魔杖菜单/悬浮球均可生成」（实为只打开设置面板）、外观页"主题暗/亮切换·字体三档"（实为五模式+4预设主题、字体默认跟随设备）。
- **死代码**：`PageGuide.vue`、`SettingsPanel.vue` 均零引用。

## 改动内容

### 1. 统一内容模块 `src/core/guide-content.ts`（新建）

- 章节数据：`GuideChapter { id, icon, title, brief, steps: OnboardingStep[] }`。原 22 步归并为 7 章：
  - `quick-start`（4 步）：概念 → 填 API → 保存（done 自动）→ 生成入口说明 → 首次生成（done 自动）→ 完成。**条目池不再逛条目库**，概念步一句话带过"内置默认条目开箱即用"。
  - `pool`(4步) / `generation`(3步) / `prompt`(1步) / `worldinfo`(3步) / `filter`(4步) / `appearance`(2步)——内容取自原 22 步对应段，精简文字量。
- 页内指引：`PageHint { icon, title, brief, points: string[] }` 结构化定义（一句话本页是干什么的 + 3-6 条要点），8 个 tab + 3 个弹窗（条目库/条目生成/正则库）共 11 份，替代散落的 HTML 长文；GuidePopover 渲染结构而非 v-html。
- **修正全部事实错误文案**（上面列的三处），向导与页内指引共用一份数据后不再漂移。
- `OnboardingStep` 接口与聚光灯机制（`data-tour` 锚点、done 基线检测、pendingTab/pendingAction 信号）原样保留，仅步骤数据迁入新模块；`onboarding.ts` 保留状态 refs 与触发函数。

### 2. 章节化向导与 🎓 入口

- `openOnboarding(chapterId?)`：带参从该章第 1 步开始；无参弹出**章节菜单**（新 UI，可并入 OnboardingWizard 或独立小组件）：每章一行（图标+标题+简述+步数），`quick-start` 章用现有 `isApiReady`/`lastOptionsGeneratedAt` 实时显示"未完成/已完成"徽章。
- 进度点改为按当前章节步数显示；章内翻页，末步完成即关闭。
- `FloatingSettings.vue` 的 🎓 按钮 → `openOnboarding()`（无参）→ 章节菜单。

### 3. 首启欢迎卡 `WelcomeCard.vue`（新建）

- 挂 `FloatingRoot.vue`（与 OnboardingWizard 并列，全局单实例，Teleport 到 body，z 用 popover 档）。
- 触发：启动后延迟 ~3s（等悬浮球/面板挂载就绪）且 `!onboarding_done` 时弹出；**弹出瞬间置 `onboarding_done = true`**（沿用现有哲学：中途刷新也算看过，不骚扰）。
- 形态：非全屏小卡片，锚定悬浮球坐标（取 `floating-state.ts` 的 bubbleX/bubbleY，fallback 屏幕右下角），宽 `min(340px, vw-16)`。
- 内容：一句话介绍（"AI 每次回复后自动生成一组行动选项，点选即发送"）+ 三步图示（配 API → 自动生成 → 点选项）+ 按钮「配置 API，开始使用」（开设置面板并直接进入 quick-start 的 api-fill 步）/「稍后再说」（仅关闭）。

### 4. 卡点召回链路

- `onboarding.ts` 新增模块级信号 `onboardingRemedy = ref<'api' | null>` + 会话内一次性节流标记。
- `generator.ts` generateOptions 的 API 未配置分支：保留 toastr 报错，同时置 `onboardingRemedy = 'api'`；`FloatingSettings.vue` watch 消费 → 打开面板、切 api tab、直接跳 quick-start 的 api-fill 步。**每会话只自动弹一次**，之后仅报错不拦截。
- `ActionOptionsPanel.vue` 空状态：API 未解析到时显示「去配置 API」按钮，触发同一信号。
- `FloatingBubble.vue`：disabled 态加 `title`（"未配置 API / 条目池为空，点击打开设置"）；点击行为维持现状（开设置）。

### 5. ❓ 页内指引精简 + 窄屏修复

- `GUIDE_CONTENTS` 与 3 个弹窗 guideHtml 的消费方全部切到 `guide-content.ts` 的 `PageHint` 渲染（brief + 要点列表）。
- `GuidePopover.vue`：改 props 接收结构化数据；顺带修窄屏问题——锚点在屏幕下半部时翻转到锚点上方弹出，不再压成 120px 内滚小窗。

### 6. 死代码清理与文档同步

- 删除 `PageGuide.vue`（零引用）；顺带删除同样零引用的 `SettingsPanel.vue` 遗留抽屉版（如想保留请说明）。
- AGENTS.md 组件清单同步移除这两项，并补记新的引导架构（guide-content.ts / 章节菜单 / 欢迎卡 / 召回信号）。

## 不做的事

- 不改 `data-tour` 锚点埋点方式与聚光灯定位机制（300ms 轮询等定位链路脆弱但已工作，本次不动）。
- 不新增 schema 字段/迁移（`onboarding_done` 复用；章节无状态、就绪徽章实时检测）。
- 不动条目池/生成/提示词等业务逻辑。

## 实施顺序

1. `guide-content.ts` 内容迁移与文案修正（纯数据层，先行）
2. `onboarding.ts` 章节化 + `OnboardingWizard.vue` 改造 + 章节菜单 + 🎓 入口
3. `WelcomeCard.vue` + FloatingRoot 挂载 + 首启触发
4. 召回链路（generator 信号 → 面板空状态按钮 → 悬浮球提示）
5. ❓ 指引切数据源 + GuidePopover 改造 + 窄屏翻转
6. 死代码删除 + AGENTS.md 同步
7. `pnpm build` + `npx vue-tsc --noEmit` 自查（watch 由你跑着，完成后你手动刷新酒馆）

## 浏览器验证步骤（完成代码后按 AGENTS.md 约定先向你确认再执行）

1. 恢复出厂（或清 `extension_settings.choice`）→ 刷新 → ~3s 后欢迎卡弹出；点「配置 API」→ 直接进 quick-start 向导聚焦 API 表单；填完保存 → ✓ 自动前进到"生成入口"步。
2. 🎓 按钮 → 章节菜单出现 7 章；点「条目池」→ 从条目池章第 1 步开始，不再从全局第 1 步重放。
3. 拔掉 API → 面板点「生成」→ toastr 报错 + 设置面板自动打开并聚焦 api 步（二次点生成仅报错）；面板空状态出现「去配置 API」按钮。
4. 各 tab ❓ → 新精简指引（要点列表）；把设置面板拖到屏幕下部再点 ❓ → 弹层向上翻转。
5. 悬浮球 disabled 态有 title 提示；console 无新增报错/警告。
